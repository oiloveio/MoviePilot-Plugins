# ANiStrmHub

抓取 ANi 的 RSS 订阅源，为每一集生成 `.strm` 文件，交给 MoviePilot 刮削入库，Emby/Jellyfin 直连播放。

fork 自 [honue/MoviePilot-Plugins](https://github.com/honue/MoviePilot-Plugins) 的 ANi-Strm，改名以避免与原版及其他 fork（ANiStrmPlus、ANiStrmPro）撞插件 ID。

## 功能

- **订阅同步**：按执行周期抓取订阅源，为新集生成 strm
- **订阅源与加速源**：各自维护一份地址列表，在下拉框输入新地址即可添加，列表中每项都可设为当前或删除，并以标签标注「内置 / 自定义」及说明。首次安装预填已加速的镜像订阅源（默认，开箱即用）、ANi 官方订阅源和两个加速节点；内置地址失效时直接删除、换成新地址即可，不依赖插件更新。用哪个由用户选，插件不在后台自动切换
- **加速源的作用范围**：只作用于 strm 中的视频播放链接，用于提升媒体服务器的播放速度，不作用于订阅源（RSS）的获取
- **本地中转**：媒体服务器或播放设备本身不走代理、打不开需要翻墙的视频链接时，strm 改为指向 MoviePilot，由 MoviePilot 经局域网代理拉取视频再转发，支持拖动进度，播放设备无需任何代理设置。MoviePilot 访问地址填公网地址时链接自动附带密钥，在家和在外都能直接播放；填局域网地址时免密钥、仅限局域网
- **详情页操作台**：重建直链、重建目录结构、补全历史剧集、连通性检测在插件详情页点击按钮执行（需 MoviePilot 登录），执行前可看到本地 strm 的线路分布
- **存放方式**：平铺存放，或按剧集分目录（每部剧一个文件夹）
- **本地 strm 维护**：重建直链、重建目录结构
- **补全历史剧集**：回溯找回 RSS 滚动窗口之外的老集数
- **连通性检测**：逐个检查已保存的订阅源能否获取；用真实视频直链逐个实测官方直链与已保存加速源的首包耗时和下载速度，标注当前使用与最快线路，给出建议但不自动修改配置

## 安装

在 MoviePilot 插件市场添加本仓库地址后安装。V3 宿主装 `plugins.v3/anistrmhub`，V2 宿主装 `plugins.v2/anistrmhub`——两份实现的业务逻辑逐字节一致，只有 import 路径不同（V2 没有 `app.sdk.*` 稳定出口）。

## 工作原理

### 订阅源：用户选择，不自动切换

订阅源只有一个配置值，每次运行只抓这一个源。抓取失败时本次任务结束，失败原因写入运行状态，下次定时运行再试，不在后台切换到其他源——自动切换会让"这条直链来自哪个源、走哪条线路"变成运行时才能确定的隐藏状态，历史版本因此产生过把加速源前缀套到失效镜像域名上的坏链接。

订阅源与加速源各有一份由用户维护的列表（配置键 `subscription_list` / `accelerator_list`），下拉框的选项就来自这两份列表。代码里的内置地址（`BUILTIN_SUBSCRIPTIONS`、`BUILTIN_ACCELERATORS`）只在配置里还没有列表键时（首次安装、从旧版本升级）填入，之后完全以用户列表为准——内置地址失效时用户直接删除、换成新地址即可，插件照常可用。在下拉框直接输入的地址，保存时由 `init_plugin()` 并入列表并写回配置，之后一直保留，直到用户删除。当前订阅源留空时取列表第一条；列表也为空则报"未配置订阅源"，不会回退到代码里的内置地址。连通性检测逐个实测两份列表中的地址供对比，是否换用由用户决定。

### 配置页的地址管理列表

插件配置页是后端下发的 JSON 组件树，由 MoviePilot 前端的 `FormRender` 渲染。下拉菜单的每个选项拿不到自己的数据，放不了删除按钮，所以「设为当前」和删除放在下拉框下方的列表里，借助 `FormRender` 的两项能力实现：

- `onClick` 事件函数：直接修改表单数据，删除即从列表数组移除，设为当前即改写当前值
- `show` 表达式与 `{{ }}` 动态属性：删除后该行隐藏，下拉选项也由列表实时计算，同步消失

在移植的 `FormRender` + Vuetify 3.7.3（MoviePilot V2/V3 前端版本）页面上实测时发现两处渲染器限制，已规避：

- `FormRender` 总会给组件传入默认插槽，会盖掉 `VBtn` 的 `icon` 属性，按钮显示为空白。图标改为作为 `VIcon` 子组件放进按钮
- `show` 的实现是往 `style` 上设置 `display`：`style` 为字符串时隐藏直接失效；为对象时被就地修改，Vue 比较前后引用相同而跳过更新。带 `show` 的元素一律不设 `style`，样式放在内层元素

### 链接模型：订阅源决定默认线路，加速源可以覆盖

ANi 直链的结构是 `{线路前缀}/{季度}/{文件名}?d=mp4`，其中 `季度/文件名?d=mp4`（资源路径）在所有镜像、所有加速节点之间完全一致。订阅源分两类：

| 订阅源 | 下发的直链 | 类型 |
|---|---|---|
| `api.pili.cc.cd` | `https://pro.pili.cc.cd/resources.ani.rip/2026-7/xxx?d=mp4` | 镜像，已加速 |
| `aniapi.op5.de5.net` | `https://pro.op5.de5.net/resources.ani.rip/2026-7/xxx?d=mp4` | 镜像，已加速 |
| `api.ani.rip` | `https://resources.ani.rip/2026-7/xxx?d=mp4` | 官方，未加速 |

两种典型用法：

- **开箱即用**：默认的镜像订阅源，加速源留空。strm 直接使用镜像下发的已加速链接
- **自行管理加速**：选 ANi 官方订阅源，再单独配置加速源。以后更换加速节点，在详情页点击新线路重建即可

所有写入 strm 的地方统一经过 `compose_link()`：

1. 加速源留空：原样使用订阅源下发的链接
2. 填了加速源：先用 `to_official_link()` 按资源路径还原官方直链、剥掉镜像自带的那层加速，再用 `build_proxied_url()` 套上该加速源：`加速源 + / + 原host + path + query`

镜像链接上直接叠加速源会叠出 `pro.op5.de5.net/pro.pili.cc.cd/resources.ani.rip/...` 这样的两层壳，第 2 步的先剥后套就是为此。

加速源在每次拉取开始时用当次样本直链实测一次：测不通则本次不生成、在运行状态中写明原因，下次定时运行再试，不会改用其他线路生成。这一步只判断通不通，线路快慢由连通性检测负责。

### 本地中转：给不走代理的媒体服务器用

strm 由媒体服务器或播放设备直接访问，它们通常不走代理，而 ANi 官方直链（`resources.ani.rip` → `cloud.ani-download.workers.dev`）在大陆网络下通常需要代理才能访问，社区加速节点也可能不稳定。本地中转把"走代理"这一步挪到 MoviePilot：

```text
媒体服务器 / 播放设备 ──局域网──▶ MoviePilot /api/v1/plugin/ANiStrmHub/relay/resources.ani.rip/... ──代理──▶ ANi 官方
```

- **接入方式**：中转地址 `{MoviePilot 访问地址}/api/v1/plugin/ANiStrmHub/relay` 作为一条加速源，与其他加速源用同一套 `compose_link()` 拼接，strm 内容为 `http://192.168.1.10:3000/api/v1/plugin/ANiStrmHub/relay/resources.ani.rip/2026-7/xxx?d=mp4`。挂在 MoviePilot 已有的网页端口上，不需要额外开放或映射端口
- **转发**：`relay_video()` 经「代理服务器」向上游发起流式请求，按 256KB 分块转发，边收边发，不落盘。上游的跳转在 MoviePilot 这一侧经代理完成，媒体服务器无感知
- **拖动进度与文件大小**：上游对象存储对 Range 请求只返回 `Content-Range`，不带 `Content-Length` 与 `Accept-Ranges`，媒体服务器因此拿不到文件大小。中转一律以 Range 向上游请求：客户端带 Range 时原样转发并按 `Content-Range` 补齐本段长度；不带 Range 时向上游取 `bytes=0-`，按 200 返回整个文件并给出文件总大小；HEAD 只向上游取 1 字节，读出文件总大小
- **访问控制**：一个 strm 只能写一个地址，所以由「MoviePilot 访问地址」决定链接形态：

  | MoviePilot 访问地址 | strm 链接 | 在家 | 在外 |
  |---|---|---|---|
  | 局域网地址 | `http://192.168.1.10:3000/api/v1/plugin/ANiStrmHub/relay/resources.ani.rip/...`，不带凭证 | ✅ | 只能由媒体服务器在家里拉流（如转码播放） |
  | 公网地址 | `https://mp.example.com:8443/api/v1/plugin/ANiStrmHub/relay/{密钥}/resources.ani.rip/...` | ✅ | ✅ |

  规则：带正确密钥的请求任何来源都放行；不带密钥的请求只在确认来自局域网时放行。只看来源 IP 不可靠——MoviePilot 前面有反向代理时，外网请求到达时的来源是反向代理自己的局域网地址，0.11.0 就因此把外网请求当成局域网放行。现在同时满足两条才算局域网：访问地址（`Host`）是局域网地址；整条转发链（直接连接方、`X-Forwarded-For`、`X-Real-IP`）都是局域网地址。已实测 Lucky 反向代理会把公网域名作为 `Host` 传给 MoviePilot。如果你的反向代理把 `Host` 改写成内网地址、又不传 `X-Forwarded-For`，外网请求仍可能被当作局域网，这种情况请把 MoviePilot 访问地址设为公网地址，让链接带上密钥
- **为什么用插件专用密钥，而不是 MoviePilot 的账号或 API 令牌**：接口需要免登录（`allow_anonymous`），因为 strm 由媒体服务器、播放器在后台访问，无法交互登录，凭证只能写在链接里。能读到 strm 或播放地址的人就能拿到凭证，这一点任何写在链接里的凭证都一样（Emby/Jellyfin 播放地址中的 `api_key`、Plex 的 `X-Plex-Token` 同理）。区别在于泄露后的影响：MoviePilot 的 API 令牌能调用 MoviePilot 的全部接口；中转密钥只能用来转发 ANi 官方视频，重置即作废
- **只转发 ANi 视频**：只接受 `resources.ani.rip` 下"季度/文件名"结构的地址，其余一律返回 403，不会被当作通用代理
- **跳转缓存与连接复用**：经代理每新建一条加密连接的开销可能达到数秒，而播放一个视频要先连 `resources.ani.rip` 再跳转到 `workers.dev`。中转记住跳转后的最终地址（6 小时），之后直接访问；内部使用长连接会话，拖动与连续读取复用已建立的连接。最终地址失效时自动回到原始地址重新跳转。实测经某局域网代理：拖动进度首包由 6.9 秒降到约 1 秒
- **文件名编码**：从请求的原始路径（`raw_path`）截取上游地址，不做解码再编码，保证文件名与 ANi 官方地址逐字节一致

已用真实网络验证：
- 局域网：经真实局域网代理，订阅同步生成的 strm 可直接播放，起播首包约 1 秒，拖动进度约 1 秒，与直连结果逐字节一致，`ffprobe` 正确读出 1080P H.264 + AAC
- 外网：经 Lucky 反向代理的公网域名访问 0.11.0 的中转，起播首包 2.4 秒、平均 780KB/s，拖动 2.5～3 秒，`ffprobe` 成功；同时也证实了 0.11.0 的外网请求会被当成局域网放行，已在 0.12.0 修复

### 连通性检测：订阅源与播放线路分开测

两层回答的是不同问题，不能混为一谈：

| 层 | 测什么 | 决定什么 |
|---|---|---|
| 订阅源 | RSS 能否获取、条目数、响应耗时 | 能否发现新番 |
| 播放线路 | 取一条真实视频直链，分别经官方直链与每个已保存的加速源访问 | 起播快慢、播放是否卡顿 |

每条线路用 `measure_playback()` 流式下载视频开头 4MB（8 秒封顶，读够即断开），得到两个指标：

- **首包耗时**：从发起请求到收到第一块视频数据，包含 `resources.ani.rip` → `cloud.ani-download.workers.dev` 的跳转，对应起播等待
- **下载速度**：首包之后的持续吞吐，对应播放是否流畅。ANi 1080P 单集约 570MB / 24 分钟，折合约 400KB/s；低于这个值必然卡顿，达到两倍以上才有余量

"当前使用"的判定：填了加速源就是该加速源；没填就是订阅源自带的线路（镜像源为镜像的加速节点，官方源为官方直链）。结论规则：当前线路不可达时提示最快的可用线路；其他线路比当前快 30% 以上才建议更换，避免单次测速的波动导致来回改配置。检测只给建议，不修改配置。

视频直链的探测一律不走 MoviePilot 代理：strm 最终由 Emby/Jellyfin 或播放器直接访问，它们不经过 MP 的代理，探测必须站在同样的网络视角，否则会出现"插件测得通、播放器播不了"的假阳性。测速从 MoviePilot 所在主机发起，播放设备与其处于同一网络时结果有代表性。

### 连通性判定：状态码 + 内容双重校验

`probe_latency_ms()` 发一个 64 字节的 Range 请求，两层都通过才判定可达：

1. HTTP 状态码为 200/206
2. 响应内容确实是视频数据：`Content-Type` 不是 `text/html`/`application/json` 这类网页格式，内容开头不是 `<!doctype`/`<html`/`<?xml`/`{` 等错误页特征

只看状态码不够：服务器可能返回 200 但响应体是错误页。遇到不认识的容器格式且无错误页特征时保守放行，避免误杀。

### 补全历史剧集：集数回溯 + 多季度目录尝试

`ani-download.xml` 是滚动窗口，只含近期资源。同一部剧全部集数的直链只有集数数字不同，因此可以从本地已有的最早一集往前递减集数构造候选。

季度目录按剧集**首次收录**的月份命名，不按每集实际上传日期——实测确认一拳超人第三季真实起点在第 25 集、SPY×FAMILY 第三季真实起点在第 38 集，都落在比本地当前最早一集更靠前的季度文件夹里。因此某一集在当前季度目录探测不通时，会按月份距离由近到远尝试本地已知的其它季度目录（每集最多 4 个），全部试过才停止回溯这部剧；命中的季度作为下一集的优先候选。

限流设计：严格串行、探测间隔固定、单次任务总探测数上限、每集季度候选数上限。确认可达才写入。

### strm 存放方式

- **平铺存放**：全部文件直接放在存储目录下
- **按剧集分目录**：`storageplace/{剧名}/{完整文件名}.strm`，Emby/Jellyfin 一个文件夹对应一个剧集条目，刮削更干净。多季度的剧季度信息本来就在标题里，会自然分到不同文件夹，不需要额外套 `Season 01` 子目录

剧名解析（`SERIES_TITLE_RE` + `StrmFileService.extract_series_title()`）只有一份实现，供"订阅同步"和"重建目录结构"共用。ANi 命名格式固定为 `[ANi] 剧名 - 集数 [1080P][Baha]...`，两个要点：

- 集数不一定是整数，实测存在 `- 12.5 [`（半集）和 `- 電影 [`（剧场版），因此不复用只认整数的 `EPISODE_NUM_RE`，改用 `- 任意非方括号内容 [`
- 剧名本身可能含 ` - `（如 `Fate - Grand Order`），因此剧名部分用贪婪匹配取最后一个分隔点

解析不出来的文件平铺到根目录，不猜测目录名。剧名转目录名只挡路径分隔符——实测样本（2650 个文件）中没有文件系统非法字符、没有超长文件名。

改了存放方式后，用「重建目录结构」把已有文件搬到对应位置：双向支持，也能把历史版本留下的季度目录（`2026-7/`）里的文件收进剧名文件夹；纯本地移动，不改内容不发网络请求，目标已存在时保留原文件不覆盖，搬完清理空目录。

### 目录决策只有一处

新文件的目录只由 `__task` 经 `__resolve_relative_dir()` 决定，其余任务不参与：

| 任务 | 文件位置来源 |
|---|---|
| `__task` 订阅同步 | `__resolve_relative_dir()` |
| `__backfill_task` 补全历史剧集 | `ref_file.with_name()`，与参照文件同目录 |
| `__refresh_subscription_task` 重建直链 | 原地 `write_text()`，不移动 |

给后两者各自再实现一遍剧名解析会造成重复实现，规则变更时容易漏改、导致同一部剧一半在文件夹里一半在根目录。

### 维护任务的执行与保护

维护类任务会扫描并改写同一批 strm 文件，因此同一时间只运行一个：详情页按钮在有任务运行时不可用，接口也会拒绝第二个任务。任务在后台线程执行；MoviePilot 重启或插件重载后，残留的「运行中」状态会改为「已中断」，不会一直卡在运行中。

扫描改写流程（`__rewrite_local_strm()`）对几类现实情况有针对性处理：

- **抽样实测**：同一集在各条线路上的资源路径完全相同，线路通了文件就在。重建直链先实测 3 个文件，确认目标线路可达后其余直接改写。此前逐个实测，2713 个文件按约 2 秒/个要一百多分钟

- **文件在任务执行期间消失**：文件列表在任务开始时一次性取出，而任务可能运行数十分钟，期间目录监控转移文件属正常现象。这类文件按"已移除"单独计数，不计入"无法识别"
- **目标地址整体不可达**：连续探测失败达到 `MAX_CONSECUTIVE_PROBE_FAILURES`（10 次）即中止任务并在摘要中说明，不再逐个文件继续消耗超时

逐文件的成功/失败记录为 debug 级别，仅前若干条失败输出 warning，结果以任务结束时的汇总为准。

### Emby 容器代理设置

❗ **环境变量必须额外设置一条小写的 `http_proxy`**：[ffprobe 源码](https://github.com/FFmpeg/FFmpeg/blob/master/libavformat/http.c#L218C48-L218C48) 使用 `getenv_utf8("http_proxy")`，对大小写敏感，缺这一条会导致无法提取媒体信息。

```yaml
- 'http_proxy=http://127.0.0.1:7890'
- 'HTTP_PROXY=http://127.0.0.1:7890'
- 'HTTPS_PROXY=http://127.0.0.1:7890'
```

Clash 侧记得为 `resources.ani.rip`、`aniopen.an-i.workers.dev` 配置代理规则。

### 媒体服务器不走代理时：本地中转

以 MoviePilot 与代理服务部署在同一台 NAS 上为例：

1. 确认 MoviePilot 的代理服务器设置（配置项 `PROXY_HOST`）已指向局域网代理，例如 `http://192.168.1.2:7890`；也可以不改 MoviePilot 的设置，在插件本地中转的「代理服务器」里单独填写
2. 插件配置页「本地中转」：开启「启用本地中转」，「MoviePilot 访问地址」填 MoviePilot 的公网访问地址（只在家里看也可填局域网地址），保存
3. 打开插件详情页，点「连通性检测」确认本地中转线路可达
4. 在详情页「重建为」中点击「本地中转」：全部 strm 改为经本地中转播放，并设为当前加速源

### 自建反代当加速源

社区加速源（pili/op5 这类免费部署的 Cloudflare Worker）天然不稳定。也可以用 GOST、Nginx 等工具自建一个 "Proxy Everything" 风格的反向代理，把反代地址输入到「加速源」，用法与社区加速源完全一致。

## 已知限制

- **不能补历史季度**：「拉取季度筛选」只能在 RSS 当前滚动窗口（近期约 50~60 条）里筛选。原版依赖的目录扫描接口（`openani.an-i.workers.dev`）已确认 429 限流失效，现有可用镜像（pili/op5）也未实现该协议——POST 目录接口返回的是普通网页而非 JSON，"全量补季度"没有可用的接口基础
- **详情页不会自动刷新**：`get_page()` 是静态组件树，后台任务的进度不会自动推送到页面。执行按钮后 MoviePilot 会重新加载一次详情页；之后查看进度请点「刷新状态」
- **加速源切换的识别边界**：「重建直链」通过 `extract_resource_path()` 定位与域名无关的资源路径再重建地址，因此改订阅源、改加速源或清空加速源都能正确处理，不依赖"记住"原先套的是哪个前缀
- **MoviePilot 访问地址为局域网地址时只在局域网内可用**：外网客户端直接访问 strm 地址（直链播放）时打不开；由媒体服务器在 NAS 上拉流再转给客户端（如转码播放）时不受影响。需要外网直链播放时改用公网地址
- **中转密钥写在 strm 链接里**：能读到 strm 文件或播放地址的人可以拿到密钥，请只在可信的媒体库中使用；怀疑泄露时重置密钥并在详情页重建直链
- **中转冷启动较慢**：每个视频首次经中转访问时要经代理新建连接，慢的代理可能要十几秒；之后复用连接，拖动约 1 秒
- **本地中转依赖 MoviePilot 运行**：中转接口随插件注册，插件停用或 MoviePilot 重启期间，经中转的 strm 无法播放；视频流量会经过 MoviePilot
- **测速是单点单次**：测速在 MoviePilot 主机上进行，每条线路只测一次，受当时网络波动影响；播放设备与 MoviePilot 不在同一网络时，结果只能作参考

## 技术存档

### 订阅源实测结果

RSS 能拉到 ≠ 视频能播：RSS 端点与其给出的下载直链经常不是同一个域名，直链域名可能单独被拦截或限流。逐个用 `Range` 请求实际验证视频直链后：

| 地址 | RSS | 视频直链 | 结论 |
|---|---|---|---|
| `https://api.pili.cc.cd/ani-download.xml` | 200 | `pro.pili.cc.cd` 返回 206 + 正确 mp4 数据 | ✅ 内置 |
| `https://aniapi.op5.de5.net/ani-download.xml` | 200 | `pro.op5.de5.net` 返回 206 + 正确 mp4 数据 | ✅ 内置 |
| `https://api.ani.rip/ani-download.xml` | 200 | `resources.ani.rip` 返回 206 + 正确 mp4 数据（非大陆网络环境下测得） | ✅ 内置 |
| `https://aniapi.v300.eu.org/ani-download.xml` | 200 | `proi.v300.eu.org` 返回 Cloudflare "Just a moment..." JS 挑战页（403） | ❌ 不可用 |
| `https://aniapi.td.ee/ani-download.xml` | 200 | `ani.td.ee` 返回 "This website has been temporarily rate limited" | ❌ 不可用 |
| `http://open.ani.rip/ani-download.xml` | 403 | — | ❌ 不可用 |
| `https://openani.an-i.workers.dev/ani-download.xml` | 429 | — | ❌ 不可用 |

官方 RSS（`api.ani.rip`）给出的直链域名是裸的 `resources.ani.rip`，而可用的社区镜像已经把它换成了自己的反代域名。

### 踩过的坑

- **`?d=mp4` → `.mp4` 后缀改写导致 404**：早期版本 `touch_strm_file` 改写过 RSS link 的查询参数，实测目标反代站点因此路由不到资源。现在资源路径与查询参数原样保留，不做任何后缀改写。同样的问题在 ANiStrmPro 的 `_convert_url_format` 里也存在
- **`get_res(headers=...)` 是整体替换不是合并**：探测请求直接传只含 `Range` 的 headers 会丢掉默认 `User-Agent`，裸请求被 Cloudflare 当可疑流量拦成 403，可达链接被误判为不可达。改用 `update_headers()` 合并
- **`scheduler.shutdown()` 默认 `wait=True` 导致保存配置卡死**：保存配置会先走 `init_plugin()` → `stop_service()`，若上一次耗时任务仍在后台线程运行，保存会被阻塞到任务跑完。改为 `shutdown(wait=False)`，用真实 APScheduler（非 mock）验证：从阻塞 2 秒+ 降到立即返回。此前单测把调度器整个 stub 掉，这类生命周期/并发问题测不出来
- **只看 HTTP 状态码判定可达不可靠**：服务器可能返回 200 但响应体是错误页，需要配合 Content-Type 与内容特征校验
- **`requests.Response` 的布尔值等于 `response.ok`**：4xx/5xx 响应本身为 `False`，用 `if not response` 判断会把"HTTP 403"误报成"无响应(连接失败或超时)"，排查时方向完全错误。必须用 `response is None`
- **订阅镜像下发的直链自带加速层**：pili/op5 镜像给出的是 `pro.pili.cc.cd/resources.ani.rip/...`，直接再套加速源会叠成两层壳，而且"加速源留空"时实际并不是官方直链。统一经 `compose_link()` 先还原官方直链再套加速源

### MoviePilot 框架调研结论

对 [jxxghp/MoviePilot](https://github.com/jxxghp/MoviePilot) 源码的调研结论，当前未使用，存档备查：

- 插件路由挂载逻辑（`app/adapters/web/plugin/routes.py`）中，`get_api()` 返回的字典若带 `"allow_anonymous": True`，会跳过标准的登录态/apikey 鉴权，路由变为匿名可访问。官方插件仓库的 `clashruleprovider` 采用此写法：路由匿名放行，在函数体内自行校验 URL 参数中的 token
- `RequestUtils`（`app/adapters/network/http.py`）除一次性下载的 `get_res()` 外，另有 `get_stream()`（`@contextmanager`，底层为 `requests.Session`），支持真流式转发

早期版本据此实现过 Relay 转发（插件内反向代理），后因该方向本属专业工具职责、且加速源的前缀拼接能力已能覆盖自建反代场景而移除。

### v0.8.0

依据真实运行日志（17007 行）定位并修复三处缺陷。

**修复**

- **维护任务缺少熔断**：目标地址整体不可达时会逐个文件继续探测。日志中出现过一次任务运行 72 分钟、1461 个文件全部超时、最终零改动的情况。现在连续失败达到 `MAX_CONSECUTIVE_PROBE_FAILURES`（10 次）即中止，并在摘要中说明原因
- **文件中途消失被误判**：文件列表在任务开始时一次性取出，而任务可能运行数十分钟，期间目录监控转移文件属正常现象。此前按"无法识别"计数并逐条输出警告（单次 499 条）。现在按"已移除"单独计数，降为 debug
- **维护任务并发执行**：多个维护开关同时勾选时会并发扫描并改写同一批文件，彼此可见对方写入中途的状态，探测请求也成倍增加。现在串成队列按顺序依次执行，单个任务异常不影响后续任务

**优化**

- 逐文件流水日志降为 debug，仅保留汇总与前若干条失败详情。此前单次任务可输出近 5000 行 INFO
- 两个维护任务的扫描改写循环合并为共用实现 `__rewrite_local_strm()`，三条保护逻辑只有一份
- 功能命名统一：订阅同步 / 重建直链 / 应用加速源 / 重建目录结构 / 补全历史剧集 / 连通性检测；存放方式为平铺存放 / 按剧集分目录
